# NIGHT SHIFT

1–4 player online co-op PvE survival horror for iOS and Android. Godot 4.7, GDScript,
Mobile renderer, landscape, touch-first.

## Running

| What | Command (from the project folder) |
|---|---|
| Play (editor or desktop) | open in Godot 4.7 and press F5, or `tools/godot.sh` |
| All tests (unit + full-mission integration) | `tools/godot.sh --headless --fixed-fps 60 res://tests/test_runner.tscn` |
| One test file | `... res://tests/test_runner.tscn -- --ns-test=test_core` |
| Compile every script | `tools/godot.sh --headless res://tools/check_scripts.tscn` |
| Online co-op smoke test (2 real processes) | `tools/mp_smoke.sh client_leaves` / `host_leaves` / `relay` (internet path) |
| Run the internet relay server locally | `tools/godot.sh --headless --path server/relay -- --port=9080` |
| Reset data resources to defaults | `tools/godot.sh --headless res://tools/generate_content.tscn` |

Dev flags (after `--`): `--ns-solo[=<mission_id>]`, `--ns-intro` (play the story intro now), `--ns-intro-shots=<dir>`, `--ns-host`, `--ns-join=<ip>`, `--ns-host-online`,
`--ns-join-online=<CODE>`, `--ns-relay=<ws(s)://url>`, `--ns-room=<CODE>`, `--ns-autostart=<n>`,
`--ns-bot`, `--ns-seed=<n>`, `--ns-port=<n>`, `--ns-profile=<name>` (separate save folder,
for running several instances), `--ns-quality=low|medium|high`, `--ns-touch` (force touch
HUD on desktop), `--ns-screenshot=<file>@<sec>`, `--ns-quit-after=<sec>`.

Desktop dev controls: WASD move, mouse look (click to capture), Shift sprint, C crouch,
E interact (hold), F flashlight, Q use item, X drop, 1–4/Tab select, G ping, Esc pause.

## Asset pipeline (all assets are original, generated by these scripts)

| Assets | Command |
|---|---|
| PBR texture sets (`assets/textures`) | `python tools/textures/gen_textures.py` then `python tools/textures/patch_imports.py` |
| Flashlight cookie | `python tools/textures/gen_cookie.py` |
| Survivor model, rig, 13 animations | `blender --background --python tools/blender/build_survivor.py` |
| THE HUNTER model, rig, 9 animations | `blender --background --python tools/blender/build_hunter.py` |
| Props, devices, doors, fixtures | `blender --background --python tools/blender/build_props.py [-- --only=a,b]` |
| Item pickups, notes, elevator car | `blender --background --python tools/blender/build_items.py` |
| Sound library (`assets/audio`) | `python tools/audio/gen_audio.py` then `python tools/audio/patch_imports.py` |
| Inventory icons (from item models) | `tools/godot.sh res://tools/render_icons.tscn` (windowed) |
| App icon (2D painted Hunter, all sizes + Android layers) | `python tools/paint_app_icon.py` |
| Asset manifest | `python tools/gen_manifest.py` |

After regenerating, run `tools/godot.sh --headless --import`. Visual QA scenes:
`res://tools/asset_preview.tscn` (characters/animations) and `res://tools/facility_tour.tscn`
(rooms, power on/off, FPS + draw calls per shot). Add `-- --ns-quality=low|medium|high`.

Rendering notes: static models are batched per room into MultiMeshInstance3D
(`MeshBatcher`), materials are shared from `MaterialLibrary` by name, the global shader
parameter `ns_quality` drops normal mapping/detail sampling on Low, and characters are driven
by AnimationTrees built in `SkinnedCharacterVisual` from replicated gameplay state.

## Internet play (relay)

Players on different networks (mobile data, different homes, behind NAT) connect through a
small WebSocket relay in `server/relay/` (a headless Godot project, no game logic). The host
taps **Host online** and gets a 6-character code (e.g. `K7QM2X`); friends type that code in
the join box. The game host stays authoritative; the relay only forwards packets inside a room.

* Relay address priority: `--ns-relay=` flag > Settings → Gameplay → *Relay server* >
  project setting `nightshift/network/relay_url`. Use `wss://` for a hosted relay.
* Deploy: `server/relay/Dockerfile` runs anywhere Docker runs (VPS, Fly.io, Railway);
  `server/relay/render.yaml` is a ready Render blueprint. The server reads `PORT`.
  Then put its URL (`wss://<host>`) into `nightshift/network/relay_url` in `project.godot`.
* **Live relay:** `wss://nightshift-relay.onrender.com` (Render free, Frankfurt), built from the
  public repo github.com/13polik/nightshift-relay (copy of `server/relay/`). After changing the
  relay, push to that repo and trigger a deploy in Render (no auto-deploy webhook for a
  public-URL repo). Free tier sleeps after ~15 min idle; the first connection then takes ~1 min.
* Self-host on a PC: run the relay command above and forward TCP port 9080 on the router;
  players enter `ws://<public-ip>:9080` in Settings.
* Traffic is ~160 KB/min per 2-player room, so one small instance handles many rooms.

## Architecture

```
scripts/
  core/          Log, Events (global bus), Settings, SaveManager (+backends), Loc,
                 Content (data registry), Router (scene flow + overlay), SeededRng, CmdArgs
  networking/    Net (lobby/session, listen-server authority), transport abstraction
                 (ENet for LAN, RelayMultiplayerPeer over WebSocket for internet), LAN discovery, join codes
  player/        PlayerCharacter (owner-predicted movement, server-validated), health,
                 flashlight, camera, interactor, CharacterVisual interface (+dev visual,
                 +AnimatedCharacterVisual adapter for rigged models)
  inventory/     server-authoritative slot inventory
  interaction/   Interactable base + InteractionService (server-timed holds, net ids),
                 doors, searchables, objective devices, elevator, revive, notes
  enemies/       EnemyBase (server sim + client interpolation), EnemyPerception,
                 EnemyBrain FSM + one class per state, HunterBrain, EnemyManager
  missions/      MissionController, MissionGenerator (seeded variation), MissionDirector
                 + ObjectiveHandlers, EventDirector + MissionEvents, NoiseSystem,
                 PowerGrid, MissionState (replicated flags)
  environments/  FacilityLayout (JSON), FacilityBuilder, PropFactory, materials, env
  audio/         Audio (buses, cue library, pooled 3D one-shots), ambience + tension music
  progression/   Profile, ProgressionRules, EntitlementProvider (future cosmetic store)
  ui/            theme, menus, lobby, results, HUD, touch controls, settings
data/            .tres content (items, enemy, mission, events, cosmetics, perks, kits)
                 and the facility layout JSON
localization/    en.json, pl.json
tests/           unit + integration suites
```

### Authority model
The host is the authoritative server for lobby state, mission state/flags, objectives,
events, enemies, health, inventories, interactions, pickups and rewards. Each client owns
only its own movement (responsive on mobile); the server sanity-checks speed and relays it.
Remote entities are interpolated ~100 ms in the past. Solo play uses
`OfflineMultiplayerPeer` through the same code paths.

### Content is data
* New item / cosmetic / perk / kit / event / mission: add a `.tres` in `data/`.
* New objective mechanic: add an `ObjectiveHandler` subclass and register it.
* New event: subclass `MissionEvent`, reference it from an `EventData`.
* New enemy type: new `EnemyData` (+ optional `EnemyBrain` subclass / custom states).
* New art: `scenes/environments/props/<kind>.tscn`, `scenes/environments/devices/<kind>.tscn`,
  `res://materials/<name>.tres`, `res://audio/cues/<id>.ogg` and
  `data/player/character_model.tres` override the generated development assets without
  code changes.

## Status / known limitations
* Art and audio are original, script-generated assets (Blender + NumPy). They are stylised
  rather than hand-sculpted; any asset can be replaced by dropping a file at the same path.
* Online play: LAN (ENet, IP / LAN discovery) and internet (relay, 6-character room code).
  No host migration: if the host leaves, clients return to the menu with a message.
* Mid-mission joining is refused by design (lobby only).
* Mobile builds: see "Building for phones" below. Release (store) signing is not set up yet.

## Building for phones

Requirements on Windows: Godot 4.7.2 export templates, Android SDK (build-tools 35+), JDK 17
(Editor Settings > Export > Android > Java SDK Path; here `~/.jdks/jdk-17.0.21+9`).

| Target | Command | Output |
|---|---|---|
| Android (debug-signed, installable) | `tools/godot.sh --headless --export-debug "Android" build/android/NightShift.apk` | `build/android/NightShift.apk` |
| iOS (Xcode project) | `tools/godot.sh --headless --export-debug "iOS" build/ios/NightShift.ipa` | `build/ios/NightShift.xcodeproj` |

* Android install: `adb install -r build/android/NightShift.apk` (USB debugging on), or copy the
  APK to the phone. For Google Play use a release keystore (`--export-release`, AAB via Gradle build).
* iOS: the preset holds a placeholder team id (`TEAMID0000`). On a Mac open
  `build/ios/NightShift.xcodeproj`, pick your team under Signing & Capabilities, then run on a
  device or Product > Archive. Windows can only produce the Xcode project.
* Splash: `tools/paint_splash.py` -> `assets/ui/splash/` (engine boot splash, boot screen and the
  iOS launch storyboard).
